# bitrix24-leads

Заявки из Telegram-бота → **Битрикс24** без дублей, с очередью на случай, когда CRM недоступна.

- **Пошаговая форма в боте (FSM):** имя → телефон (кнопкой «Поделиться номером» или вручную, с проверкой формата)
  → что нужно → подтверждение. `/cancel` на любом шаге.
- **Заявка сразу в CRM** с источником «Telegram-бот», полем «Что нужно клиенту» и Telegram клиента в контакте.
- **Без дублей по телефону** (номер в любом формате приводится к `+7XXXXXXXXXX`):
  - открытая заявка уже есть → новая не создаётся, просьба уходит **комментарием в её ленту**;
  - прошлая закрыта, клиент известен → «Повторное обращение» к тому же контакту;
  - новый клиент → новая заявка.
- **Оба режима Битрикс24:** классический (лиды) и простой (контакт + сделка) — режим определяется сам.
- **CRM недоступна** (таймаут, лимит, техработы) → клиенту «заявка принята», заявка в очереди,
  бот досылает её раз в минуту и сообщает менеджеру.
- **Уведомление менеджеру** в Telegram со ссылкой «Открыть в Битрикс24».
- **Настройка CRM через API** при запуске: источник лидов и поле создаются, если их нет; повторный запуск ничего не дублирует.

## Запуск
```bash
python -m venv venv
venv\Scripts\pip install -r requirements.txt
copy .env.example .env    # B24_WEBHOOK, BOT_TOKEN, ADMIN_ID
python bot.py
```
Входящий вебхук: портал → Приложения → Разработчикам → Другое → Входящий вебхук → права **CRM (crm)**.
Проверить права: `ВЕБХУК/scope.json` должен вернуть `["crm"]` (пустой список — права не сохранились).

## Проверка
- `tests/test_offline.py` — 15 проверок: нормализация телефонов; правило против дублей в классическом режиме;
  очередь: CRM лежит → заявка ждёт → CRM вернулась → доставлена ровно один раз.
- `tests/live_dedupe.py` — на настоящем портале в его режиме: все три ветки правила против дублей, номер в другом
  формате, поля и источник; создаёт записи `[тест]` и удаляет их.
- Живой тест (2026-10-07): две заявки из бота с одного номера → в CRM одна сделка и один контакт,
  вторая просьба — комментарием в ленте сделки.
